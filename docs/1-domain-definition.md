## 1. 프로젝트 개요

### 목적

개인 사용자가 할일(Task)을 효율적으로 생성·관리·추적할 수 있는 인증 기반 할일 관리 애플리케이션을 제공한다.

### 배경

- 기존 일정 관리 도구들은 카테고리별 분류 및 종료 시간 표현이 미흡하다.
- 사용자는 할일을 카테고리로 구분하고, 완료 여부 및 마감 초과 여부를 한눈에 파악하고자 한다.
- 인증된 사용자만 데이터에 접근할 수 있어 개인 정보를 보호한다.

---

## 2. 도메인 용어 정의 (Ubiquitous Language)

| 용어 | 정의 |
|------|------|
| **사용자 (User)** | 회원가입 후 인증을 통해 애플리케이션을 사용하는 개인 |
| **할일 (Task)** | 사용자가 등록한 단일 작업 단위. 제목, 설명, 카테고리, 종료일, 상태를 가짐 |
| **카테고리 (Category)** | 할일을 분류하기 위해 사용자가 직접 정의하는 그룹 레이블 |
| **종료일 (Due Date)** | 할일을 완료해야 하는 목표 날짜 및 시간 |
| **상태 (Status)** | 할일의 현재 진행 상태. `PENDING(대기중)`, `COMPLETED(완료)`, `OVERDUE(기한 초과)`로 구분 |
| **완료 (Completed)** | 사용자가 명시적으로 완료 처리한 할일 상태 (`COMPLETED`) |
| **기한 초과 (Overdue)** | 종료일이 현재 시각보다 과거이며 아직 완료되지 않은 할일 상태 (`OVERDUE`) |
| **필터 (Filter)** | 카테고리 또는 상태 기준으로 할일 목록을 좁혀 보는 조회 조건 |
| **인증 (Authentication)** | 이메일과 비밀번호로 사용자 신원을 확인하는 절차 |

## 3. 핵심 도메인 (Core Domain)

### 3.1 User (사용자)

**속성**
- `id` : 고유 식별자
- `email` : 로그인 식별자 (유일값, 표준 형식 준수)
- `password` : 암호화된 비밀번호 (최소 복잡도 요구)
- `createdAt` : 가입 일시

**행위**
- 회원가입 (register)
- 로그인 / 로그아웃 (login / logout)
- 본인 계정 정보 조회 (getProfile)

---

### 3.2 Category (카테고리)

**속성**
- `id` : 고유 식별자
- `userId` : 소유 사용자 참조
- `name` : 카테고리 이름 (사용자 범위 내 유일값)
- `createdAt` : 생성 일시
- `updatedAt` : 최종 수정 일시

**행위**
- 카테고리 추가 (create)
- 카테고리 이름 수정 (rename)
- 카테고리 삭제 (delete) — 하위 할일 처리 정책 포함 (BR-05)

---

### 3.3 Task (할일)

**속성**
- `id` : 고유 식별자
- `userId` : 소유 사용자 참조
- `categoryId` : 소속 카테고리 참조 (선택)
- `title` : 할일 제목
- `description` : 상세 설명 (선택)
- `dueDate` : 종료일시 (선택)
- `status` : `PENDING` | `COMPLETED` | `OVERDUE`
- `createdAt` : 생성 일시
- `updatedAt` : 최종 수정 일시

**행위**
- 할일 생성 (create)
- 할일 수정 (update)
- 완료 처리 (complete)
- 완료 취소 / 재활성화 (reopen)
- 할일 삭제 (delete)
- 상태 자동 판별 (resolveStatus) — 조회 시점에 현재 시각과 dueDate를 비교하여 결정

## 4. 비즈니스 규칙

### 인증 및 계정

- BR-01: 모든 기능(카테고리, 할일 CRUD 포함)은 인증된 사용자만 접근할 수 있다.
- BR-02: 이메일은 전체 시스템에서 유일해야 한다.
- BR-03: 비밀번호는 저장 전 반드시 단방향 암호화(해시)되어야 한다.
- BR-10: 이메일은 표준 이메일 형식(예: user@example.com)을 준수해야 한다.
- BR-11: 비밀번호는 최소 8자 이상이며, 영문·숫자·특수문자를 포함해야 한다.

### 카테고리

- BR-04: 동일 사용자 내에서 카테고리 이름은 중복될 수 없다.
- BR-05: 카테고리 삭제 시 해당 카테고리에 속한 할일의 `categoryId`는 `null`(미분류)로 처리한다.

### 할일 상태

- BR-06: `dueDate`가 설정되어 있고 현재 시각이 `dueDate`를 초과하였으며 완료되지 않은 할일의 상태는 `OVERDUE`로 표시한다. (조회 시 실시간 판별)
- BR-07: 사용자가 완료 처리한 할일은 `dueDate` 초과 여부와 무관하게 `COMPLETED` 상태를 유지한다.
- BR-08: `dueDate`가 없는 할일은 `OVERDUE`가 될 수 없으며, 완료 전까지 `PENDING` 상태이다.

### 데이터 소유권

- BR-09: 사용자는 본인이 생성한 할일과 카테고리만 조회·수정·삭제할 수 있다.
