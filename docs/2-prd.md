## 1. 제품 개요

### 1.1 목적

인증 기반 할일 관리 웹 애플리케이션으로, 개인 사용자가 할일을 카테고리별로 분류하고 기한 초과 여부를 실시간으로 파악할 수 있도록 한다.

### 1.2 배경

기존 일정 관리 도구는 카테고리 분류와 기한 초과 상태 표현이 미흡하다. 바쁜 일상을 보내는 직장인과 가정주부가 간편하게 할일을 등록·추적·완료할 수 있는 가볍고 직관적인 도구가 필요하다.

## 3. 범위 정의

### 3.1 In-Scope (구현 대상)

| 기능 영역 | 세부 기능 |
|-----------|----------|
| 할일 관리 | 할일 생성·조회·수정·삭제, 완료 처리·취소, 상태 필터(PENDING / COMPLETED / OVERDUE) |
| 카테고리 관리 | 카테고리 생성·수정·삭제, 카테고리별 할일 필터 |
| 사용자 정보 관리 | 회원가입, 로그인·로그아웃, 내 계정 정보 조회 |

### 3.2 Out-of-Scope (구현 제외)

- 푸시 알림 / 이메일 알림
- 할일 공유 / 협업 기능
- 반복 일정(Recurring Task)
- 파일 첨부
- 소셜 로그인 (OAuth)
- 다크 모드 (Phase 2)
- 다국어 지원 (Phase 2)
- 모바일 네이티브 앱

## 4. 기능 요구사항

> 도메인 정의서의 유스케이스(UC) 및 비즈니스 규칙(BR)과 매핑됩니다.

### 4.1 인증 (Authentication)

| ID | 요구사항 | 우선순위 | 관련 UC / BR |
|----|---------|---------|-------------|
| FR-AUTH-01 | 이메일·비밀번호로 회원가입할 수 있다 | Must | UC-01, BR-02, BR-03, BR-10, BR-11 |
| FR-AUTH-02 | 이메일은 전체 시스템에서 유일해야 한다 | Must | BR-02 |
| FR-AUTH-03 | 비밀번호는 최소 8자, 영문·숫자·특수문자를 포함해야 한다 | Must | BR-11 |
| FR-AUTH-04 | 로그인 성공 시 JWT(HS-512) 토큰을 발급한다 | Must | UC-02 |
| FR-AUTH-05 | 로그아웃 시 클라이언트 토큰을 무효화한다 | Must | UC-03 |
| FR-AUTH-06 | 모든 API는 유효한 JWT 없이 접근 불가하다 (인증 필수) | Must | BR-01 |

### 4.2 카테고리 관리 (Category)

| ID | 요구사항 | 우선순위 | 관련 UC / BR |
|----|---------|---------|-------------|
| FR-CAT-01 | 인증 사용자는 카테고리를 생성할 수 있다 | Must | UC-04, BR-04 |
| FR-CAT-02 | 동일 사용자 내 카테고리 이름은 중복될 수 없다 | Must | BR-04 |
| FR-CAT-03 | 카테고리 이름을 수정할 수 있다 | Must | UC-04 |
| FR-CAT-04 | 카테고리 삭제 시 해당 카테고리의 할일 categoryId는 null로 처리된다 | Must | UC-04, BR-05 |
| FR-CAT-05 | 본인이 생성한 카테고리만 조회·수정·삭제할 수 있다 | Must | BR-09 |

### 4.3 할일 관리 (Task)

| ID | 요구사항 | 우선순위 | 관련 UC / BR |
|----|---------|---------|-------------|
| FR-TASK-01 | 제목(필수), 설명(선택), 카테고리(선택), 종료일(선택)로 할일을 생성할 수 있다 | Must | UC-05 |
| FR-TASK-02 | 할일 목록을 조회할 수 있다 | Must | UC-06 |
| FR-TASK-03 | 카테고리 또는 상태(PENDING / COMPLETED / OVERDUE)로 필터링할 수 있다 | Must | UC-06, UC-10 |
| FR-TASK-04 | 할일의 제목·설명·카테고리·종료일을 수정할 수 있다 | Must | UC-07 |
| FR-TASK-05 | 할일을 COMPLETED 상태로 전환할 수 있다 | Must | UC-08, BR-07 |
| FR-TASK-06 | COMPLETED 상태의 할일을 다시 PENDING/OVERDUE로 복구할 수 있다 | Must | UC-11, BR-06, BR-08 |
| FR-TASK-07 | 할일을 삭제할 수 있다 | Must | UC-09 |
| FR-TASK-08 | dueDate가 현재 시각보다 과거이고 미완료인 할일은 OVERDUE로 표시한다 (조회 시 실시간 판별) | Must | BR-06 |
| FR-TASK-09 | dueDate가 없는 할일은 OVERDUE가 되지 않으며 완료 전까지 PENDING이다 | Must | BR-08 |
| FR-TASK-10 | 본인이 생성한 할일만 조회·수정·삭제할 수 있다 | Must | BR-09 |

### 4.4 사용자 정보 (User Profile)

| ID | 요구사항 | 우선순위 | 관련 UC / BR |
|----|---------|---------|-------------|
| FR-USER-01 | 인증 사용자는 본인의 계정 정보(이메일, 가입일)를 조회할 수 있다 | Must | UC-01 |

## 5. 비기능 요구사항

### 5.1 성능

| ID | 요구사항 |
|----|---------|
| NFR-PERF-01 | 할일 목록 조회 응답 시간 500ms 이하 (일반 네트워크 환경 기준) |
| NFR-PERF-02 | 페이지 초기 로드 3초 이내 |

### 5.2 보안

| ID | 요구사항 |
|----|---------|
| NFR-SEC-01 | 비밀번호는 bcrypt 등 단방향 해시로 저장 |
| NFR-SEC-02 | JWT 서명 알고리즘은 HS-512 사용 |
| NFR-SEC-03 | API 응답에 비밀번호 필드를 절대 포함하지 않는다 |
| NFR-SEC-04 | SQL Injection 방지를 위해 파라미터화 쿼리를 사용한다 |

### 5.3 호환성

| ID | 요구사항 |
|----|---------|
| NFR-COMPAT-01 | 반응형 웹으로 구현하여 모바일(320px 이상)과 데스크탑(1280px 이상) 모두 지원 |
| NFR-COMPAT-02 | 최신 Chrome, Safari, Edge, Firefox 지원 |

### 5.4 유지보수성

| ID | 요구사항 |
|----|---------|
| NFR-MAINT-01 | 프론트엔드·백엔드·DB가 분리된 3-tier 구조로 독립 배포 가능하게 구성 |
| NFR-MAINT-02 | API는 RESTful 설계 원칙을 준수한다 |

## 6. 기술 스택

### 6.1 프론트엔드

| 항목 | 선택 |
|------|------|
| 런타임 | Browser (SPA) |
| 프레임워크 | React 19 |
| 언어 | JavaScript (TypeScript 미사용) |
| 서버 상태 | TanStack Query |
| 전역 상태 | Zustand |
| 스타일 | Tailwind CSS |

### 6.2 백엔드

| 항목 | 선택 |
|------|------|
| 런타임 | Node.js 24 |
| 언어 | JavaScript (TypeScript 미사용) |
| 프레임워크 | Express 5 |
| DB 드라이버 | pg (node-postgres) |
| 인증 | JWT (HS-512) |

### 6.3 데이터베이스

| 항목 | 선택 |
|------|------|
| DBMS | PostgreSQL |

### 6.4 아키텍처

```
[브라우저 / 반응형 웹]
        │
        ▼
[Frontend: React 19 SPA]
        │  REST API (HTTP/JSON)
        ▼
[Backend: Express 5 / Node 24]
        │  pg 라이브러리
        ▼
[Database: PostgreSQL]
```

## 7. 플랫폼 및 디자인 방향

### 7.1 플랫폼

- **반응형 웹**: 모바일(스마트폰·태블릿)과 데스크탑 모두 지원
- 별도 네이티브 앱은 제공하지 않음

### 7.2 디자인 시스템

- Tailwind CSS 유틸리티 클래스 기반으로 일관된 UI 구성
- 컴포넌트 단위 재사용 가능한 스타일 적용
- 직관적인 레이아웃으로 페르소나 B(30대 주부)도 별도 학습 없이 사용 가능한 수준의 UX 목표

### 7.3 Phase 2 대상 (현재 범위 외)

- 다크 모드 지원
- 다국어 지원 (i18n)

## 9. 가정 및 제약사항

| 구분 | 내용 |
|------|------|
| 가정 | 단일 사용자 환경을 우선 고려하며, 대규모 동시 접속은 고려하지 않는다 |
| 가정 | dueDate 기반 OVERDUE 판별은 서버 응답 시점의 시각 기준으로 처리한다 |
| 제약 | TypeScript 미사용 (프론트엔드·백엔드 모두 JavaScript) |
| 제약 | ORM 미사용, pg 라이브러리로 직접 SQL 작성 |
| 제약 | Phase 1 내 다크 모드·다국어 구현 없음 |
| 제약 | 소셜 로그인 미지원, JWT 단독 인증 |
| 제약 | 배포 환경은 별도 정의하지 않음 (로컬 개발 환경 기준으로 진행) |
